# Аудит жестов и подзадач (04.11.2026, до правок)

## Как устроены строки дел

| Компонент | Что делает | Где используется |
|---|---|---|
| `GestureTaskRow` | framer-motion `drag="x"` + `dragDirectionLock`; свой таймер долгого нажатия 480 мс на pointer-событиях; свайп влево сразу удаляет; свайп вправо — отступ, только если передан `onIndent` | все списки дел |
| `ReorderableList` + `DragHandle` | framer `Reorder.Group/Item`, тянется только за ручку ⋮⋮ (`touch-action: none`) | `DayTaskList` (Сегодня, день, история, списки «Удел»/«Прочее»), `SectionBlock`/`SphereTaskItem` (сфера, раздел, подзадачи) |
| `TaskActionSheet` | меню по долгому нажатию; «Сделать подзадачей…» предлагает только дела текущего списка | все списки |
| `TodaySphereList` | весь блок — framer `drag="y"` за ручку, отпускание ищет окно по `[data-drop-window]` | «Сегодня» |

Две реализации списка: `DayTaskList` (плоский, без свайпа вправо) и `SectionBlock` + `SphereTaskItem` (с подзадачами и отступом).

## Почему жесты ненадёжны

1. **Нет порога и соотношения осей.** `dragDirectionLock` у framer фиксирует ось по первым пикселям движения. Чуть косой вертикальный скролл, начатый на строке, становится горизонтальным свайпом: строка едет, страница не скроллится.
2. **Вложенные drag.** Строка (`drag="x"`) лежит внутри `Reorder.Item` (drag по y через `dragControls`). Обе обработки висят на одних pointer-событиях, а `Reorder` пересчитывает раскладку по `layout`. На iOS это иногда даёт «прыжки» строки и потерю свайпа.
3. **`Reorder` в контейнерах с `overflow: hidden`** (скруглённые карточки разделов, `overflow-hidden` у строки) обрезает поднятую строку. Автоскролла у краёв нет, поэтому длинный список не переставить. Каждый кусок дел между намазами на «Сегодня» — отдельная группа `Reorder`.
4. **Долгое нажатие.** Таймер сбрасывается при `pointerleave`, а на iOS это событие приходит при малейшем сдвиге пальца. `select-none` стоит только на строке: заметка и мета-строка внутри кнопок при долгом нажатии всё равно выделяются, iOS показывает лупу или меню.
5. **Удаление без отмены.** Свайп дальше 110 px или быстрый флик удаляет сразу и безвозвратно, вместе с подзадачами и без подтверждения.
6. **«Сделать подзадачей» свайпом** есть только в сфере и разделе. В `DayTaskList` (то есть на «Сегодня» и экране дня) `onIndent` не передаётся.
7. **Перенос «Удел»/«Прочее».** Когда перетаскивание начинается (`onDragStart` → `moving`), в каждое окно вставляются зоны «Перенести сюда». Раскладка сдвигается прямо под пальцем, а координата отпускания сравнивается с уже сдвинутыми зонами. Цели — только «под намазом окна», поставить блок между делами нельзя. Блок возвращается `dragSnapToOrigin`, автоскролла нет.

## Как хранится подзадача

Два независимых механизма:

- **Дело внутри дела** — `Task.parentId` (поле задачи). Показывается вложенным только в сфере и разделе (`SphereTaskItem`). На «Сегодня» списки «Удел»/«Прочее» отфильтровывают подзадачи (`!t.parentId`), поэтому подзадача без даты на «Сегодня» не видна. В окнах дня подзадачи стоят плоско, без признака вложенности.
- **Пункты** — `checklists[taskId]: ChecklistItem[]` (отдельное поле снимка, без даты, времени и сферы).

Решение: «дело внутри дела» делается через `parentId`, чек-лист не трогается.
