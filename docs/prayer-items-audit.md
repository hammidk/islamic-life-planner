# Аудит пунктов намазов (04.11.2026, до правок)

## Как хранится

| Что | Где | Формат |
|---|---|---|
| Отметка самого намаза | `prayersByDate[YYYY-MM-DD][prayerId]` (`togglePrayer`) | `true/false`, по датам |
| Пункты намаза | `checklists[prayerId]` — ключ `fajr`, `dhuhr`, `asr`, `maghrib`, `isha`, `tahajjud` | `ChecklistItem { id, title, done }`, плоский массив |
| Пункты дела | `checklists[taskId]` — тот же словарь | тот же `ChecklistItem` |
| Подзадачи дела | `Task.parentId` — это отдельные дела | полноценные `Task` |

Отметка намаза и его пункты не связаны: выполнение пунктов не меняет `prayersByDate`, и наоборот.

Пункты намаза хранятся по id намаза, а не по дате: у Фаджра один и тот же список каждый день, отметки пунктов тоже не сбрасываются. В этом промпте поведение не меняется, расписание и отметки намазов не трогаются.

## Как рисуется

Компонент списка пунктов уже один — `EditableChecklist`. У него три обёртки:

- `Checklist` (данные из контекста):
  - **«Сегодня» → карточка намаза** `PrayerRow`: зелёный (или красный) блок каждого окна, в том числе **Тахаджуд**; подсказки «Азкары / Дуа / Чтение Корана»; `tone="onPrimary"`.
  - Строка дела в списках дня (`TaskItem`, раскрывающиеся пункты).
  - Страница дела `TaskDetail`.
- `DraftChecklist` — пункты ещё не созданного дела (`FullTaskScreen`).

Отдельной страницы или окна намаза в приложении нет. `PrayerTimeline` на Главной показывает только время, «История» — только количество отмеченных намазов. Значит, пункты намаза есть в одном месте: в карточке намаза на «Сегодня», включая окно Тахаджуд.

## Чем пункты отличаются от подзадач дел

| | Подзадачи дел (`Task.parentId`) | Пункты (`ChecklistItem`) |
|---|---|---|
| Вложенность | 2 уровня, `utils/taskTree` | нет, плоский список |
| Свайпы | `useRowGestures`: удалить / вынести / сделать подзадачей | нет |
| Перестановка | dnd-kit, долгое нажатие | нет |
| Описание | есть (`description`) | нет |
| Меню по долгому нажатию | есть | нет |
| Удаление | свайп, меню, тост «Отменить» | только очистить текст (или ✕ в черновике) |
| Правка по тапу, Enter — следующий | есть | есть (промпт 1) |

## Решение

`EditableChecklist` превращается в `ChecklistEditor` с параметрами `allowNesting` и `allowNote` на том же слое жестов (`SwipeRow`/`useRowGestures`), dnd-kit (`SortableList`) и функциях дерева из `taskTree`, обобщённых до узла `{ id, parentId? }`.

- Намазы: `allowNesting` и `allowNote` включены, подсказки остаются.
- Пункты дел и черновика: вложенность и описание выключены, жесты и перестановка общие.
